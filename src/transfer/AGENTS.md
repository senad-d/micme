# Pi transfer modules

- `contracts.ts` owns the shared S/C/M/E/L/P/K data and service signatures, the new action literals, setting defaults and CLI flags. Use type-only imports for Pi and existing capture/lifecycle types; do not bring the extension entry point into a headless dependency graph. B/Q runners and validators stay in `test/live-native/`.
- `options.ts` is a pure decoder. Use `getTransferOptions()` from `../config.ts` for effective settings and `writeMicmeConfigValues()` for atomic saves. The shell wins over the agent-dir file; optional strings use `""` to unset and lists are JSON array **strings**. The decoder does not qualify runtime IDs; check exact membership in the catalog and device enumeration at the operation boundary. Do not expand or log private prompt, endpoint, or credential values. A selected provider may look up its named key in the process environment only, not in saved config. Keep `micme.schema.json` and `micme.example.json` aligned with the contracts.
- `capture.ts` supplies verified evidence and audio; `host.ts` connects to the session owner in `../extension.ts`. The host owns generation checks, editor delivery and shutdown. Use the existing `MicmeOperationPhase` there; it is not a dependency of the headless contracts. Compose the existing action list with `MICME_TRANSFER_ACTIONS`. Do not change Worker v1 or enable new services on the ordinary capture path by default.
- `catalog{,-data}.ts` records exact artifacts; `managed.ts` verifies installations; `engine{,-evidence}.ts` supplies loaded native evidence (the catalog looks up qualified data with `getEngineEvidence`). Route inference in `recognition.ts` and schedule work in `jobs.ts`. `language{,-data}.ts` owns per-take language and local finishing. `setup.ts` and `settings.ts` present qualified choices; Try It does not depend on the optional native engine.
- `library.ts` owns rows and verified audio; `retention.ts` owns confirmed prune policy and startup enforcement. `history-view.ts` and `import.ts` own the corresponding view and local media jobs. `provider.ts`, `hook.ts`, `process-final.ts` and `processing-view.ts` handle explicitly selected final-only operations, not ordinary dictation or editing the prompt.
- No work at module import: no discovery, worker, mic, DB, writes, network, credential reads or view registration. Construct services on demand after the caller's opt-in and check the operation signal. An unavailable shell must not claim a verified artifact, recording, device, save or successful delivery.

Root `npm run typecheck` includes these modules; `npx --no-install tsc --project src/transfer/tsconfig.json` scopes the TypeScript entry points. Use the existing Node test runner (`node --test --test-reporter=dot test/<name>.test.mjs`); no new runner. Run `npm run build:doctor` and `npm run check:pack` after changing the headless dependency graph. Package changes belong in the root scripts/allowlist; this directory adds no runtime dependency or install step.
