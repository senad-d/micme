# P5 language intent and local finishing

## What was measured

[Take observations](transfer-q-p5-takes.jsonl) and [per-take rule tags and error counts](transfer-q-p5-scores.jsonl) record **16 local file attempts**, not a Pi, Handy, or microphone benchmark. Each uses the public `recognizeFile` entry point, a pinned installed Whisper weight and binary, a disposable empty config/home, and the exact public PCM. No provider, account, network at replay, or live editor is involved. The two FLEURS controls are **additional P5 fixtures**; they do not fill unrelated frozen P1 slots. There is no `before` comparison to P1 and no latency, cross-rig, or parity result. `raw` is the ASR text before P5 finishing; `cleaned` is the returned `Final.local`. The file route did not expose native call counts or an actual device identity, so neither is inferred from its CPU request; even compute is `unknown` when no backend was observed. `rawFinal` is the public result observation, not the internal decoder's completion time.

| Language / condition | Raw → local | What the paired controls show |
|---|---|---|
| French → French, base, lines 1–2 | WER 10% → 10% (2 substitutions / 20 words) | Explicit `fr` with inconsistent `ja,en` preferences retains French. `Aoclande` and `portes` are wrong. Turning on rules does not guess a correction for `Aoclande`. |
| French → French, small, lines 14–15 | WER 5% → 5% (1 substitution / 20 words) | `Hauchland` is wrong. The word list does not repair a phonetic misrecognition. This is a second exact weight, not a replacement for the base attempt. |
| Mandarin, as-spoken/simplified, lines 4–5 | CER 23.53% → 11.76% with simplified enabled (4 → 2 substitutions / 17 characters) | Same raw in both trials. The dictionary converts `這個` to `这个`; it leaves the unknown forms `村莊` and `小時` alone. The as-spoken control retains all four traditional characters. |
| Mandarin, Taiwan/Hong Kong, lines 6–7 | CER 0% → 0% against the corresponding traditional reference | This utterance uses the same written form in both regions. `script: applied` and `vocabulary: skipped (incompatible)` are distinct even though raw and local are identical. WER uses the shared word-edit scorer. CER applies the same edit counts to Unicode letters, marks and numbers after NFC (ignoring whitespace and punctuation); this includes script distinctions. The Taiwan/Hong Kong reference is “在這個迷人的村莊漫步半小時是值得的。”, a traditional rendering of the same human transcript fixed before decoding; it is not derived from ASR output.

### Separate English meaning review (not WER)

The same French PCM was submitted with the explicit `translate-en` task on both weights; compare line 3 to line 1 and line 16 to line 14. Reading each result against the French transcript and the parallel human English reference gives three checks: there are many beaches **because Auckland straddles two harbours**, with the most popular beaches in three areas. This comparison is not independent human signoff. On **base** the result substitutes “beautiful” for “numerous” and **a street** for the harbours; it keeps the three areas. On **small** it keeps the quantity, two ports and three areas, but calls Auckland “HawkeLand,” losing the named city. Neither fully preserves the source meaning. These are observed failures on these weights, not a claim that the task flag failed to select English or that other weights fail. The separate model gate rejects unsupported translation rather than treating it as transcription.

### Policy and boundary evidence

The [module tests](../transfer-language.test.mjs) exercise the manual-versus-deliberately-wrong-detector decision, compatible preference deduplication, native Auto, unavailable/short/canceled LID, the compatible candidate list at 5 seconds of measured speech, and streaming begin before any PCM. The detector and optional native engine in these tests are fixtures; no external LID adapter or bias-capable artifact was observed on the deployed native path. The optional E batch policy exposes explicit fallback reasons; the current recognition callers do not yet supply a detector, speech duration, or per-take fallback notification. No keyboard/locale guess is used. No actual multilingual streaming latency is inferred.

The same tests compare exact opt-in case/diacritic restoration (`jose` → `José`, `new york` → `New York`) against the untouched raw. Finishing skips quoted spans and nested bracketed expressions, even when the same token matches in surrounding prose. English/French fillers only remove configured or unambiguous comma-delimited asides, not “like”, “well”, `um_count` or repeated `uh`. A bare period can be removed at an eligible final. An isolated vocabulary match without independent no-speech evidence is kept and reports `echo: skipped (insufficient-speech)`. Numeric literals, code-shaped words and repeated phrases are ineligible for echo removal even on a negative. The Chinese dictionary is intentionally limited and Micme-original (MIT): `軟件…打印機` can surface as Taiwan `軟體…印表機` or remain Hong Kong `軟件…打印機`; Japanese and code spans are not eligible. These controls use fixed text, not human acoustic evidence for the frozen identifiers or filler-positive slots.

The tests also exercise the public recognition result plus the host label formatter: unchanged text carries both `vocabulary: skipped (incompatible)` and `script: applied`; finishing may improve the review text while the commit callback receives only raw. This is a component observation, not a new destination/real-editor test. A caller finishing already-confirmed text must continue to pass raw to the editor. Ordinary clip callers without a known language do not infer one from text. TUI pre-capture coverage for legacy clip language/task/preference combinations and real native bias require the owning caller/adapters and independent Pi replay; the new data does not claim those cells.
