# P1 freeze evidence (Linux CPU, before product changes)

This bundle records a **native baseline preflight, not a native performance baseline**. Every scheduled slot has a record. No native collector reached a trigger and there is no frozen timing tolerance. The separately observed Pi interaction uses scripted ASR; it qualifies the existing unsent prompt flow, not native timing, audio coverage, accuracy, or Handy parity.

## Predeclared conditions and result

The frozen `createdUtc` is the order seed. The runner orders adjacent exact-condition pair members and rotates which build goes first. The primary PCM cell schedules 20 repetitions of JFK per build. It uses the nearest *separate* `base` exports (GGUF vs ggml), manual `en`, and processing off; this is the ordinary product-configuration panel (`default`), not the apps' factory settings or an exact engine A/B. The `matched` Pi cells predeclare the same `base.en` export on the historical and current arms for continuous PCM, paced file capture and unsent destination at 40 and 80 columns, with 20 slots per arm in each cell. Exact matches remain to be observed. Handy's 20-slot paced and external-editor cells use private loopback, not Pi's paced WAV hook; the two destinations are not a single paired condition. The smaller legacy SDL and short, quiet, pause, repeat, overload, negative, language and environment controls are single-slot probes, not timing cohorts.

Before any candidate invocation, the reference-only runner attempted 20 Handy reference/reference pairs each for JFK PCM, continuous paced capture, and the continuous external-editor destination. All 120 records were unavailable at preflight and are embedded in `calibration`. No pair supplied the two finite observations needed for a nearest-rank p95 absolute difference. `toleranceMs` is empty, not zero; an independent calibration on the same provisioned reference is required before timing any candidate. The published manifest is immutable. Use a separately named run copy if adding independently authenticated receipts or a new calibration; it is not new evidence for this freeze.

The subsequent `--transfer` runs on the same path-independent manifest (with fresh output paths) each wrote 300 unavailable slots, zero completed/failed/timed out/lost, with byte-identical attempt ledgers. A run without the sidecar produced the same slot order and a generic provisioning gap. The private sidecar provided only an installed Pi host, the verified current source and the two deterministic zero-PCM fixtures; no native binaries, speech corpus, weights, older checkouts or isolated Handy application were provisioned. Planned CPU is not a bound device. Cold-process is not cold disk (`unknown` unless deliberately planned as a separate probe); warm-model, idle reload, proven cold disk and load were not observed. Physical input was never activated and there were no GPU, macOS or Windows observations. Missing timings, word errors, audio accounting and target fields are null, not measurements of zero.
